One terminal for the coding agents you already pay for.

thwip finds Codex, Claude Code, and the Antigravity CLI already signed in on your machine and lets you use them from one REPL. Switch mid-conversation without losing the thread, fail over the moment a usage limit hits, and keep one memory file per project that every agent reads and maintains.

  • No API keys needed. Each CLI keeps its own login, sandbox, and plan. thwip drives it through its published protocol.
  • Limit hits are a keypress. When one account is exhausted, pick another and your message is re-sent with context.
  • Project memory travels. A context.md per project, filed into your Obsidian vault with cross-project links.

How it works

Four things happen between typing a message and reading an answer. Each one is a real mechanism you can inspect in the source.

  1. 01

    It uses the sign-ins you already have

    On startup thwip looks for codex, claude, and agy. Codex is driven over its App Server JSON-RPC protocol, Claude Code and Antigravity through their stream-json print modes. Model lists come live from each CLI. No credential is read or copied; a direct API key for a provider takes precedence when you set one.

  2. 02

    Each provider keeps a warm session

    The first message to a provider carries the conversation once. After that only new messages are sent: Codex resumes its thread on a long-lived process, Claude Code uses --resume, Antigravity uses --conversation. Return to a provider after talking to another and it gets a short catch-up of what it missed. Session IDs are stored with the thwip session and validated on load.

  3. 03

    A usage limit becomes a switch, not a stop

    When Codex reports "you've hit your usage limit", Claude Code rejects a rate limit, Google returns RESOURCE_EXHAUSTED, or an API answers 429, thwip lists the ready alternatives and re-sends your unanswered message to the one you pick. /limits shows each account's 5-hour and 7-day windows so you can see it coming.

  4. 04

    The project remembers, whichever agent you used

    Every provider receives the project's context.md as instructions. After a real conversation, /memory update asks the current model for a revision, shows you the diff, and writes only when you confirm. Nothing is written silently.

Project memory and your second brain

One file per project holds the durable state. A vault holds the map between projects.

context.md, in the project root

Snapshot, current work as Now / Blocked / Next, architecture notes, decisions with their reasons, known issues, and dated recent changes. /memory init creates it from the repository's detected stack. It is plain Markdown, so it works with any editor and any agent, including the CLIs run outside thwip.

An Obsidian vault, connected on first run

thwip detects vaults registered with the Obsidian desktop app, or creates a folder. Each project gets an index card; hub notes are generated per stack, area, and tag; a dashboard lists everything. Projects that share a stack, area, or tag link to each other, which is what makes the graph useful. Only notes carrying generated_by: thwip are ever overwritten. Your own notes stay yours.

Kept honest by review

Updates are proposed by the model you are already talking to, limited to facts that changed, and shown as a diff. You confirm. /quit offers this once after a conversation with content.

Commands

Full reference of slash commands and keyboard shortcuts inside the thwip REPL.

Command / Shortcut Arguments Description Example
/switch <agent> [model] Hot-swaps active agent and model mid-conversation with zero lost context /switch google gemini-3.7-flash
/agents None Lists discovered local agents, API readiness, and detected CLI-only authentication /agents
/models [agent] Displays available models, context window limits, and pricing for a provider /models openai
/about or /guide None Opens the in-depth system guide and navigation manual inside the terminal /about
/limits None Inspects live session tokens, cumulative costs, and rate limit quotas /limits
/tools None Lists available universal tools (read, edit, write, run, bash, git) /tools
/history None Shows conversation turn summary and token breakdown across all models /history
/session save <name> Persists the current conversation history and file changes to disk /session save refactor-auth
/session load <name> Restores a saved session and resumes context from where you left off /session load refactor-auth
/model [id] Pick a model for the current agent from a numbered list or by ID /model
/handoff [agent] [model] Preview what transfers, what is lost, and the context fit before switching /handoff google
/compact None Summarize the conversation with the current model; the plain-text summary travels across providers /compact
/new and /resume [name] Start a fresh conversation (the current one is saved) or resume a saved one from a list /resume
/diff, /copy, /export [staged], none, [path] Show the project git diff, copy the last response, or export the conversation to Markdown with model attribution /export notes.md

/clear None Clears current conversation memory and resets session tokens /clear
